## 證據

### 1. 核心缺陷已修:同日多回合不再被合併

夾具:一條 `active` 預測鏈;同一天(2026-07-20)連跑三次 `new` + `log --outcome A`。

```
coverage 檔數: 3   檔名: 2026-07-20-01.json 2026-07-20-02.json 2026-07-20-03.json
已記錄回合數: 3 | 冷鏈候選數: 1
```

**這正是舊制的失真點**:舊制以日期為唯一鍵,三次盤點會併成 1 個檔,`COLD_STREAK=3` 永遠湊不滿,冷鏈**永不觸發**。新制三回合各自成檔,冷鏈候選如實出現 1 筆。CHG 的 pass 條件「冷鏈連續計數 +2 而非 +1」達成。

### 2. 舊格式向後相容

夾具:僅放一個舊格式 `2026-07-18.json`(無回合序號)。

```
舊檔可讀 exit=0
已記錄回合數(舊檔應計為 1): 1
續寫後檔名: 2026-07-18.json          # 未另建新檔,就地續寫
舊檔內條目數: 2 | cycle 欄: 1        # 續寫後補上 cycle 欄
```

舊檔讀為該日第 01 回合,`log` 就地續寫而非另開檔——既有使用者無需遷移。

### 3. 回合序號衝突 fail-loud

同日同時放入 `2026-07-18.json` 與 `2026-07-18-01.json`(兩者都映射到第 01 回合):

```
ERROR: 回合序號衝突:2026-07-18-01.json 與 2026-07-18.json 同為 2026-07-18 第 01 回合
       (舊格式無序號檔視為第 01 回合;請將其一改名)
exit=2
```

不靜默取其一,訊息指出兩個衝突檔名與修法。

## 一項對範圍判斷關鍵的事實

開單前量測血跡時發現:**狀態機本來就是回合制,不是日制**——`intel_daily.py:84` 的冷鏈判定讀的是「最近 3 個 coverage 檔」,紀律 21 條文也已寫「分析日」而非日曆天。真正把日曆寫死的只有 coverage 檔的唯一鍵。

這把本案從「重寫狀態機」縮到「改命名 + 改檔案鍵」,並讓 `COLD_STREAK=3` 得以原封不動保留。**若沒先量這一步,很可能連閾值一起改,日後回測就分不清差異是命名、檔案鍵還是閾值造成的。**

## 未做與理由

- **未提供舊 coverage 檔的遷移腳本**:讀取路徑已相容,遷移無實益;強制遷移反而會動到使用者的歷史盤點紀錄。
- **`COLD_STREAK` 未調整**:節奏變密後冷鏈降階會加快,這是設計意圖(已於 tracking-loop 明文說明)。是否需要隨節奏調整閾值,應由實際回測資料決定,不在本案臆測。
- **shim 未設移除的機械攔截**:僅以 CHANGELOG 載明 1.4.0 移除。若下版忘記移除,無任何機制會提醒——這是已知的弱點,依 KN-001(規則沒有機械強制就不會被執行),此處確實只有規則而無強制。
