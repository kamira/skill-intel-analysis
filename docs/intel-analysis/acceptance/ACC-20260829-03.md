## 複核到底查到了什麼

四類,其中兩類是原本不知道的:

| 類別 | 內容 | 原本知道嗎 |

| 結構性誤置 | 11 條胡塞／沙烏地的鏈被折進「美伊衝突」 | 否 |
| 個別誤置 | 7 條關鍵詞判錯 | 知道「會錯」,不知道錯哪幾條 |
| 演算法缺陷 | 分支投票平手時由 `Object.keys` 的插入順序決定 | **否** |
| 資料問題 | 兩條鏈命題一字不差而機率不同 | **否** |
| 文件錯誤 | CHG-20260829-03 把 19/19 寫成 29/9 | **否** |

第三與第五項值得單獨說。

**投票平手是靠插入順序決定的**——這在 CHG-20260829-03 的驗收裡完全沒有被抓到,
因為當時驗的是「200 條有沒有全部歸位」,而它們確實全部歸位了。
一個平手被隨機解決的分支,在總數上看起來與一個被正確解決的分支一模一樣。
**涵蓋率的檢查抓不到判準的缺陷。**

**文件把 19/19 寫成 29/9**——而站台頁面印的一直是對的,因為它從資料即時算。
這正好是「KPI 一律推導」這條規則的邊界:它管得到程式碼,管不到散文。
推導出來的數字寫進帳本之前,要用同一份資料重算過。
