## 風險分級與使用者決策(必須留痕)

本張是本 repo 目前唯一一張**高風險**變更,理由是兩件不可逆的事:

1. **repo 由 private 轉 public**。GitHub Free 方案的 Pages 只能跑在 public repo,
   因此「建 GH Page 並設為公開」在本 repo 的實際含意是整個 repo(含 `docs/` 治理帳本
   與全部 git 歷史)永久公開。fork 與快取無法收回。
2. **真實地緣政治研判對外具名發佈**。內容涉及美伊、俄烏、葉門、台海等進行中的
   衝突判斷。

依風險分級規則,高風險一律停下等人。已於實作前以選項形式取得使用者決策:

| 決策點 | 選項 | 使用者選擇 |
|--------|------|------------|
| 發佈方式 | (a) 另開獨立 public repo / (b) 本 repo 轉 public / (c) 先建好但不公開 | **(b) 把本 repo 轉為 public** |
| 公開範圍 | (a) 事件鍊摘要與機率 / (b) 每日國際觀點全文 / (c) 週報 / (d) 排除付費版 | **(a) 事件鍊摘要與機率** |

> 我在提問時已明確告知選項 (a) 可讓 repo 維持 private 且風險最低,使用者仍選擇 (b)。
> 這是使用者的決定,本張據此執行,並在此留下判斷過程。

## 公開範圍的欄位級界線(依使用者選擇 (a))

Notion 資料源 `collection://dde43243-76bf-4cd9-85f1-2596e91b808a`,1775 筆快照 / 200 條鏈。

**上站**:預測 ID、原始預測 ID、預測內容(命題陳述句)、預測百分比、機率標籤、
追蹤狀態、影響面、驗證窗口、日期、更新日期、版本序、實際結果、結果值、
以及由各版本快照壓成的機率軌跡(版本序:日期:機率)。

**不上站(逐欄具名排除)**:

| 欄位 | 排除理由 |
|------|----------|
| `觸發指標` | 完整命中／反向判準正文,屬分析方法本體 |
| `版本說明` | 建鏈理由與方法論推導全文,單筆常逾千字 |
| `校準備註` | 回測判定的推理過程 |
| `對應情境` | 連回情境推演正文 |
| `來源分析` | relation,會指回每日國際觀點全文頁 |

**整批排除**:每日國際觀點全文、週報、以及「情報分析框架(付費版)」等任何付費頁面。
站台不含任何 Notion 連結,避免成為私有頁面的索引入口。

## 已知的資料品質問題(不在本張修,但明列)

盤點真實帳本時發現三項,均為 Notion 端既有狀況,本站以「照實呈現、不粉飾」處理:

1. 有 1 筆 `原始預測 ID` 為空(建鏈時漏填),站上歸入「未掛鏈」並顯示為空鏈根。
2. 兩套 ID 慣例並存:舊制 `P-0524-03` 與新制 `P-2026-0524-03`。站上不改寫,原樣顯示。
3. 200 條鏈中有相當數量 `追蹤狀態` 為空(既未結案也未降階)。站上顯示為「未標記」,
   不臆測其真實狀態。

## 使用者故事

1. 作為讀者,我要看到 200 條鏈的清單與現況,以便判斷這套方法論是否真的在跑。
2. 作為讀者,我要看到已結案預測的命中率與 Brier,以便判斷機率標得準不準。
3. 作為讀者,我要看到機率隨時間的變化軌跡,以便看出判斷是被什麼時候的訊號推動的。
4. 作為維護者,我要站台明示資料截止日與公開範圍,以便讀者不會誤以為看到的是全部。

## 修改指引

### Goal

把 mockup 的四頁版面接上真實帳本,以 GitHub Actions 部署至 GitHub Pages。

### Global Constraints(每個 task 都要遵守)

- KPI 一律由資料推導,不得手寫(ACC-20260828-01 抓到的成因,不得重犯)
- 排除欄位清單為硬界線,程式碼中不得出現該五欄的任何值
- 轉 public 前必須先完成敏感內容掃描,且掃描結果須寫入 ACC
- 站台須明示資料截止日、公開範圍、以及「非投資／決策建議」聲明
- 地圖國家歸屬由命題文字比對推得,須在畫面上明示此為推導而非原始欄位

### Tasks(checkbox=續作點)

- [ ] T1. `site/data.js`:自 Notion 匯出的 200 條鏈(僅白名單欄位)
  - interfaces: consumes Notion 資料源 / produces `window.LEDGER`
  - test: 200 筆;無任何排除欄位;機率皆 5% 步進
- [ ] T2. `site/index.html`:四頁版面接真實資料,KPI 全部改為推導
  - interfaces: consumes `window.LEDGER` / produces 四頁站台
  - test: 開啟無 console error;KPI 數字與資料重算一致
- [ ] T3. 敏感內容掃描(token/金鑰/私鑰/內部路徑)
  - interfaces: consumes 全 repo 與 git 歷史 / produces 掃描報告
  - test: 零命中,或命中項已具名處理
- [ ] T4. `.github/workflows/pages.yml` + 啟用 Pages + repo 轉 public
  - interfaces: consumes `site/` / produces 線上站台
  - test: Actions 綠燈;站台 URL 回 200

### Interaction spec

- kind: web
- cmd: 瀏覽 `https://kamira.github.io/skill-intel-analysis/`
- artifacts: Actions run log、站台截圖

### Acceptance operation(實際操作驗收)

- **operate**:掃描 → 建站 → 本地開啟四頁 → push → 轉 public → 啟用 Pages → 開線上站台。
- **observe**:掃描命中數、console error、KPI 與資料是否一致、Actions 結論、線上站台 HTTP 狀態。
- **pass**:掃描零命中;四頁無 error;KPI 可被重算驗證;Actions 成功;線上站台可開且四頁可用。

## Risk & rollback

- 風險:轉 public 後才發現不該公開的內容 → 緩解:轉之前做掃描並人工確認欄位白名單
- 風險:git 歷史含舊敏感資料 → 緩解:掃描涵蓋歷史而非只有工作區
- **回滾的真相**:repo 可以改回 private、Pages 可以關閉,但**已被抓取的內容收不回來**。
  這一點在動作前已向使用者說明。
