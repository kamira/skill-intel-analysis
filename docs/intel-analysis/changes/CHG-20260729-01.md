## 動機
intel-analysis 目前 **24 個 md、2,582 行、全繁中、零 `.zh-tw.md` 成對檔**,與 repo 慣例衝突:本 repo 約定 **`.md` 為英文(預設)、`.zh-tw.md` 為繁中**,`bilingual_check` 對 ai-sdlc 與 autopilot 強制成對。intel 因遷移時「繁中先行」而例外至今,且**未納入 bilingual CI**。

使用者要求改為英文為主、繁中為輔,並特別指明**專有名詞須用該領域正式用語而非直翻**。此點在本 skill 尤其關鍵——內容密集引用既有情報學標準,直翻會使其失去可對照性:

| 繁中 | 正確 IC 用語 | 直翻會變成(錯誤) |
|------|-------------|-------------------|
| 分析工藝標準(ICD 203) | Analytic Standards | "analytic craft standards" |
| NATO Admiralty 評級 | Admiralty Code(source reliability × information credibility) | "reliability rating" |
| 關鍵判斷 | Key Judgments (KJs) | "key decisions" |
| 觀測指標 | Indicators(Indications & Warning, I&W) | "observation metrics" |
| 估計性語言 | Estimative Language | "estimated wording" |
| SAT 技法 | Structured Analytic Techniques (SATs) | "SAT methods" |
| 對手代言人 | Devil's Advocacy / Red Hat Analysis | "opponent spokesperson" |
| 情報池 | Holding file / intelligence pool | "intel pool" |

## 使用者故事

1. 作為**英文使用者**,我要 `SKILL.md` 與 references 以英文為預設語言,以便不必先讀中文才知道這個 skill 在做什麼。
2. 作為**情報分析專業讀者**,我要看到 ICD 203、Admiralty Code、Key Judgments 等正式用語,以便能與既有標準對照而非重新猜測對應關係。
3. 作為**繁中使用者**,我要繁中版仍完整保留,以便原有讀者不因英文化而失去內容。
4. 作為**維護者**,我要雙語成對受 CI 強制,以便日後不再單邊漂移(這正是 intel 至今例外的原因)。
5. 作為**譯者/後續維護者**,我要有一份術語對照表作為單一真相,以便同一個詞在 24 個檔案裡不會出現三種譯法。

## 決策與取捨
| 決策 | 選項 | 前提假設 | 為何這樣選 |

## 修改指引

### Goal
intel-analysis 全 24 檔改為「`.md` 英文 + `.zh-tw.md` 繁中」成對;先產出術語對照表為單一真相;完成後納入 `bilingual_check` CI。

### Global Constraints
- **術語以 `assets/glossary.md` 為單一真相**;內容翻譯不得自創與其衝突的譯法
- 專有名詞使用**該領域正式英文用語**(ICD/NATO/SAT 等既有標準),不直翻
- 繁中版**沿用原文**,不由英文回譯(避免二次失真)
- 雙語**結構平行**(`##`/`###`/``` 數一致),`bilingual_check --skill-dir skills/intel-analysis` 通過
- frontmatter `name` 保持不變(檔名與 skill 識別不動);`description` 兩語言各自完整
- 內容語意不得因翻譯改變:紀律條數、SKILL 編號、評級軸、標準引用皆須一一對應
- plugin 複本由 `build_suite.py` 同步,不手改
