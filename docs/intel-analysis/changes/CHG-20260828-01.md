## 動機

`intel-analysis` 的產出目前只有兩種形態:markdown 分析稿,與 `docs/intel/predictions/` 的
JSON 快照鏈。兩者都**沒有可視面**——鏈有幾條、跑多久、現在是活躍還是冷鏈、命中率多少,
必須自己讀 `INDEX.md` 或跑 `brier_report.py` 才知道。

使用者要的是把這些既有欄位攤成畫面,先看形狀對不對,再談要不要接資料。

## 範圍界線(明說)

**做**:四頁靜態 mockup(儀表板 / 事件鍊總表+細節 / 國家利益背景 / 分析缺口聲明)。
**不做**:不讀 `docs/intel/predictions/`、不呼叫任何 script、無後端、無建置流程。
資料是硬寫在檔案裡的**示意資料**,畫面上以 `MOCK` 標籤明示,避免被誤讀為真實情報產物。

## 使用者故事

1. 作為分析者,我要一眼看出哪些國家最常出現在事件鍊裡,以便判斷注意力有沒有押錯區域。
2. 作為分析者,我要看到每條鏈的長度與現況,以便發現「跑很久但沒動靜」的冷鏈候選。
3. 作為分析者,我要點進一條鏈就看到時間線與對應的預測版本,以便檢查機率是被什麼訊號推動的。
4. 作為讀者,我要在同一個介面讀到缺口聲明,以便知道這份分析哪裡穩、哪裡在猜。
